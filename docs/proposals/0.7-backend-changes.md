## 2. What is planned and not built

Everything from Phase 2 onward in [PHASES.md](../PHASES.md): logins and roles, departments and master data screens, award setup and form versions (R4), award sites, applications with proof and the entry limit, masking, jury and conflicts (R2), judging and score audit (R3), approval and results, on-site rounds, dashboards, the frontend, end-to-end tests and deployment. The order and the three-phase split are to be agreed in the re-plan.

## 4. Size and risk

- **Size:** about half a day to a day. One migration, about 10 schema changes and about 8 new or rewritten tests. No service code exists yet that uses the changed fields, so nothing else breaks.
- **Risk:** low. The main care points are the raw SQL for the partial indexes and CHECKs; the NULL trap in CHECKs from `ai-notes.md` #5 applies again.
- **Not affected:** the clock, errors, normalisers, storage, mailer, audit and outbox modules, health, and CI.
